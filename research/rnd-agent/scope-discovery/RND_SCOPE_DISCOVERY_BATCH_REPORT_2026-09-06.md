## Batch 4 — Architecture historical benchmark

Sources:
- `eval/architecture-agent/HISTORICAL_CASES_V0.jsonl`
- `eval/architecture-agent/HISTORICAL_GOLD_V0.jsonl`

Twelve historical architecture decisions exposed an important taxonomy problem.

Some cases contain material uncertainty but the primary judgment is a domain-specific structural tradeoff (provider-neutral boundary, canonical repo truth, docs organization, deployment supersession, persistence source-of-truth, shared harness boundary, read-model projection).

R&D should not become the architecture decision-maker merely because uncertainty exists.

Other cases contain a distinct epistemic-allocation question (whether to earn/build an orchestrator, whether an architecture capability deserves promotion, whether a broader R&D purpose is justified).

### Material taxonomy repair

Replace the Neta-specific neighbor:

`R4_NETA_PRIMARY`

with the general region:

> `R4_DOMAIN_METHOD_PRIMARY`

Definition:

> The consequential unresolved object is a domain-method judgment or tradeoff. R&D is primary only if a separable nontrivial question appears about whether/how/how much to learn before that domain decision can responsibly advance.

This change preserves Neta as one instance and admits Architecture or future earned domain methods without giving R&D their authority.

Because this changed the candidate map, discovery could not stop here.

# Candidate boundary after discovery

## R1 — EPISTEMIC-ALLOCATION CORE CANDIDATE

```text
MATERIAL_CONSEQUENTIAL decision
+ NONTRIVIAL choice whether/how/how much to learn
+ CHANNEL_SELECTION_REQUIRED or RESEARCH_METHOD_REQUIRED
→ R&D primary candidate
```

## R2 — OBVIOUS LEARNING

One cheap, reversible, legitimate discriminator already dominates.

→ execute/test first; R&D should usually bypass.

## R3 — DIRECT AUTHORITY / EXECUTION

The exact remaining material question belongs directly to OWNER/REPO/ENVIRONMENT/FIELD or execution is already justified.

→ handoff/act; R&D should not add ceremony.

## R4 — DOMAIN METHOD PRIMARY

The material unresolved object is a domain judgment (e.g. Neta signal→mechanism, Architecture structural tradeoff).

→ domain method is primary. R&D enters only for a separable learning-allocation problem.

## R5 — LOW / LOCAL

Low-consequence fact, explanation, generation, critique or reversible local action.

→ direct baseline should dominate burden/latency.

# Discovery-only interpretation

The most important discovery result is not a percentage. It is the surviving discriminating variable:

> **Uncertainty alone does not define R&D scope. Consequence alone does not define it. The candidate core requires a nontrivial decision about the allocation of learning itself.**

Domain uncertainty with an obvious authority, obvious test, or primary domain method is a neighbor, not core.
