# Agent Discovery Protocol v0

Status: `FROZEN_DISCOVERY_PROTOCOL · RESEARCH_ONLY · NO_NEW_AGENT_AUTHORIZED`
Date: 2026-09-06

## Purpose

Discover whether the ecosystem has recurring material judgment functions that are not already owned by Neta, R&D, an explicit authority, a domain method, deterministic runtime, protocol, tool, or scaffold — and determine the smallest form in which each surviving residual should exist.

This protocol does **not** assume that more agents are desirable.

The null outcome is valid:

> `NO_NEW_PEER_EARNED`

## Core principle

Do not begin from role names such as `Architecture Agent`, `Strategy Agent`, `Execution Agent`, or `Decision Agent`.

Begin from a recurring blocked decision and ask:

```text
BLOCKED MATERIAL DECISION
→ EXACT UNRESOLVED JUDGMENT
→ CURRENT OWNER / AUTHORITY / METHOD
→ RESIDUAL, IF ANY
→ SMALLEST CAPABILITY
→ COMPARATIVE TEST
→ ONLY THEN: FORM FACTOR
```

Complexity is not evidence of a distinct capability.

Multiple hypotheses, many tools, many steps, or deep reasoning can still be ordinary domain work.

## Existing ownership classes

Every candidate case must first be tested against these classes.

### 1. PEER METHOD

Current peers:
- `NETA` — product signal → competing mechanisms → discriminator → evidence-bounded intervention;
- `RND` — whether/how/how much learning or evidence acquisition is worth buying for a consequential decision.

### 2. RESOLUTION AUTHORITY

Truth/permission may belong directly to:
- `OWNER`
- `REPO`
- `ENVIRONMENT`
- `RESEARCH`
- `FIELD`

An authority is not an agent merely because it must be consulted.

### 3. DOMAIN METHOD

A specialized judgment method may own the unresolved object without deserving a persistent peer.

Examples:
- debugging;
- architecture;
- security analysis;
- legal analysis;
- finance/accounting;
- domain-specific scientific or engineering diagnosis.

The burden of proof is on internalization: repeated material value must beat borrowing expertise through Scaffold/tool/human/domain resources.

### 4. DETERMINISTIC COORDINATION / PROTOCOL

If explicit routing, state, schemas, handoffs, validators or dependency tracking can prevent the failure cheaply, repair there before creating a reasoning peer.

### 5. EXECUTION / TOOL

A system can be missing an action capability without missing a judgment capability.

`cannot execute X` does not imply `needs X Agent`.

## Residual admission gate

A case is a candidate residual only if all are true:

1. `MATERIAL` — the judgment can materially change a consequential decision, action, cost, risk, reversibility or learning;
2. `RECURRING` — the same judgment shape appears across more than one isolated incident;
3. `ORTHOGONAL` — the output is not an alias of an existing peer/authority/domain method;
4. `HIDDEN_JUDGMENT` — there is a specific discrimination the current system repeatedly misses, not merely missing knowledge;
5. `NOT_TOOLING_ONLY` — wiring/telemetry/execution/state persistence alone does not explain the gap;
6. `NOT_DOMAIN_DIAGNOSTIC_BRANCHING` — multiple hypotheses/tests internal to normal domain diagnosis do not count as epistemic-allocation or a new peer;
7. `TESTABLE` — a neighbor, falsifier and comparative baseline can be defined.

If any fail, classify the case outside peer discovery.

## Candidate progression

A surviving residual moves through these states only:

```text
OBSERVED_RESIDUAL
→ CANDIDATE_CAPABILITY
→ DISCRIMINATED_CAPABILITY
→ COMPARATIVE_DELTA_SUPPORTED
→ FORM_FACTOR_DECISION
→ PEER_ELIGIBLE | RESOURCE | PROTOCOL | TOOL | MEMORY | RETIRE
```

No candidate may jump directly from `OBSERVED_RESIDUAL` to `AGENT`.

## Form-factor discriminator

Even a real capability becomes a peer only if persistence/autonomy provides additional value.

Prefer the lowest-cost form that preserves the capability:

1. schema / validator / invariant;
2. deterministic routing or protocol;
3. reusable prompt/resource/scaffold;
4. bounded callable capability;
5. persistent peer agent.

A peer is justified only when repeated tasks require its judgment, state/lineage or stable handoff boundary often enough that invocation identity adds more value than coordination cost.

## Required capability contract

Before any comparative test, freeze:

```text
CAPABILITY_NAME
TELOS
INPUT
EXACT_JUDGMENT
OUTPUT
FIRE
NO_FIRE
PRIMARY_AUTHORITY_CEILING
NEAREST_NEIGHBORS
FAILURE_IF_ABSENT
FAILURE_IF_OVERFIRED
REVERSAL_CONDITION
```

## Comparative test

Primary comparison:

```text
A = strongest existing system available without candidate
B = A + minimal candidate capability
```

The baseline must include the resources the ecosystem already legitimately has. Do not weaken the baseline to make a candidate look useful.

A candidate win requires a **material decision delta**:
- different evidence program;
- different bounded decision;
- different option eliminated/selected;
- avoided material work;
- prevented authority violation;
- materially better reversibility/risk;
- or materially better outcome after execution.

Terminology, verbosity, elegance and confidence language do not count.

## Neighbor requirement

Every candidate must be tested against cases where it should **not** fire.

Examples:
- direct authority resolves the question;
- one cheap reversible test dominates;
- normal debugging is sufficient;
- OWNER intent is missing;
- a domain-specific method already owns the tradeoff;
- execution is already justified;
- low/local task.

A capability that improves its target cases while degrading neighbors is not ready for promotion.

## Evidence ladder

Evidence quality, strongest last:

1. same-model conceptual fit;
2. same-model controlled cases;
3. historical natural cases;
4. frozen historical/holdout with separated adjudication anchors;
5. external outcome after outputs were frozen;
6. prospective unseen natural cases;
7. independent blinded adjudication;
8. observed downstream outcome / avoided cost where measurable.

Do not convert case count from one dependent lineage into false certainty.

## Discovery stop rule

Stop broad discovery when:
- two consecutive heterogeneous batches add no new residual judgment family;
- every new case maps to an existing ownership class or already-recorded residual;
- marginal sampling no longer changes the candidate queue.

Then freeze the candidate queue and switch from broad discovery to targeted falsification.

## Agent promotion rule

A new peer requires all of:

```text
RECURRING MATERIAL FAILURE
+
ORTHOGONAL JUDGMENT FUNCTION
+
EXISTING PEER / AUTHORITY / DOMAIN-METHOD EXCLUSION
+
COMPARATIVE DECISION DELTA
+
NEIGHBOR SAFETY
+
STABLE HANDOFF BOUNDARY
+
FORM-FACTOR ADVANTAGE OVER CHEAPER RESOURCE/PROTOCOL
```

Otherwise:

> `DO_NOT_BUILD_AGENT`

## Anti-patterns

Reject these arguments:

- “This topic is important, therefore it needs an agent.”
- “The reasoning is hard, therefore it needs an agent.”
- “It has many hypotheses, therefore it needs R&D/a new peer.”
- “Experts have a job title for this, therefore the repo needs that role.”
- “There is a blank box in a lifecycle diagram, therefore fill it.”
- “A separate invocation agreed, therefore independent evidence exists.”
- “The candidate can be implemented, therefore it should exist.”

## Primary research question

> Which recurring material judgments remain unowned after subtracting Neta, R&D, explicit authorities, domain methods, deterministic coordination, execution tools and shared epistemic infrastructure — and what is the cheapest durable form that preserves each surviving judgment?
