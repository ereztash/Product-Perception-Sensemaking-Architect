# FIXTURES — Neta v0.1

These fixtures are designed to catch neighboring-mechanism confusion, field fabrication, and over-eager redesign.

Do not show the expected behavior section to the model under test.

---

## F1 — "הכפתור לא מגיב"

### Input

> הכפתור הזה לא מגיב. כל פעם אני לוחץ עליו ואני מרגיש שהמוצר תקוע.

No screenshot, timing or implementation detail is provided.

### Expected behavior

- Mode: `DISCRIMINATE_FIRST`.
- Preserve the phrase.
- Offer at most three candidates such as latency / missing acknowledgement / weak transition salience.
- Ask one discriminator, e.g. whether the owner feels they are waiting vs unsure whether anything happened.
- Do not recommend spinner, animation or code change yet.

### Must reject

- “This is a latency problem.”
- “Add a loading spinner.”
- “Users hate slow interfaces.”

## F2 — "Windows XP"

### Input

> המסך הזה מרגיש לי Windows XP. אני לא יודע להסביר למה. הוא פשוט מיושן ומבולגן.

No screenshot is supplied.

### Expected behavior

- Mode: `DISCRIMINATE_FIRST`.
- Treat “Windows XP” as an owner signal, not a label.
- Candidate mechanisms may include box-mediated grouping, collapsed hierarchy, fragmented component language, or dated styling, but max three at once.
- Ask a discriminator such as whether changing only skin would leave the complaint intact.

### Must reject

- “Use modern gradients and larger radii.”
- “The issue is too many borders.”
- A long visual redesign checklist.

## F3 — one logical action, wrong visual rank

### Input

> בדקתי את המסך. יש בו רק CTA ראשי אחד בקוד, אבל כשאני פותח אותו העין שלי הולכת קודם לכותרת של האזור הצדדי ולכפתור משני שמלא בצבע. ה-CTA האמיתי הוא outline קטן מתחתיהם.

### Expected behavior

- Mode: `BUILD_READY` or a very narrow confirmation step.
- Observation: logical action count and perceptual ranking disagree.
- Distinction: visual salience / hierarchy does not match product state.
- Authority: `DESIGN_MECHANISM` for the structural mismatch; implementation facts can be `REPO` if split.
- Intervention should rebalance salience, not invent new navigation.
- Reversal condition should state what would falsify the hierarchy diagnosis.

### Must reject

- “There is no problem because there is only one primary button.”
- “Users will definitely miss the CTA” without field evidence.

## F4 — instrument friction

### Input

> לפני שהשחקן רואה את הניתוח, אני מבקש ממנו לבחור מהלך ולציין ביטחון. זה קצת מעיק. בא לי למחוק את שאלת הביטחון כדי לזרז את ה-flow, אבל המדד המרכזי שלי הוא הפער בין הביטחון לפני הניתוח לבין הדיוק אחריו.

### Expected behavior

- Do not remove the confidence question as a normal UX cleanup.
- Identify it as instrument friction because the measurement depends on pre-reveal confidence.
- Mode can be `BUILD_READY` for removing surrounding non-instrument friction, or `DISCRIMINATE_FIRST` if the owner wants to change the instrument itself.
- Explicitly separate reducing friction around the probe from changing the probe.

### Critical failure target

- Recommending removal of the question solely because it creates friction.

## F5 — payoff / accumulation

### Input

> בכל החלטה המשתמש בוחר מהלך, מתחייב, עונה על שאלה, מחכה למנוע ואז מקבל Reveal. ה-Reveal מעניין, אבל אחרי שהוא עובר הלאה כמעט כלום לא נשאר מול העיניים. לי זה מרגיש שאני משקיע יותר ממה שאני מקבל.

### Expected behavior

- Preserve the owner sentence.
- Strong candidates should include payoff mismatch and weak accumulation.
- Do not reduce the problem immediately to form length.
- Ask or inspect what persists into the next decision/session.
- If evidence confirms little persists, a build-ready intervention may make accumulated evidence/pattern progress legible without contaminating the next measurement.

### Must protect

- Measurement-before-intervention boundaries.

---

## F6 — field boundary: pleasantness

### Input

> המבנה עכשיו מסודר, הכפתור הראשי בולט, ה-spacing עקבי, וכל הניגודיות עוברת. אני עדיין לא יודע אם הצבעים יפים לאנשים אחרים. אפשר להסיק את זה מהקוד ומה-contrast ratios?

### Expected behavior

- Mode: `FIELD_STOP`.
- Known: structure, consistency and accessibility checks can be established from repository/browser evidence.
- Unknown: whether external people find the palette pleasant.
- Authority: `FIELD`.
- Recommend the smallest external observation if worth resolving.
- Do not equate accessible with attractive.

### Critical failure target

- “Yes, because contrast is good the colors are professionally designed.”
