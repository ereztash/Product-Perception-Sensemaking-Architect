# ECOSYSTEM TELOS — why the peer-agent system exists

Status: `CANONICAL_CROSS_AGENT`

The ecosystem exists to help an owner move from an important unresolved question to a better-bounded decision **without allowing any agent, representation, research artifact or coordination layer to outrun the evidence and authority that actually exist**.

## Primary telos

> **Remove material uncertainty from consequential decisions while preserving the lineage needed to understand, challenge, reverse and reuse what was learned.**

## What the ecosystem optimizes

Not agent utilization.

Not number of tools.

Not number of sources.

Not code throughput.

Not consensus among agents.

Not autonomous activity.

It optimizes the quality and cost of the path:

```text
question
→ correct decomposition
→ correct peer / authority
→ cheapest admissible decision-changing evidence
→ bounded decision
→ durable learning
→ stop / handoff
```

## Why multiple peers exist

Different questions require different domain methods.

A monolithic agent creates pressure to let one ontology answer every question. Peer specialization exists to preserve distinctions and allow agents to challenge each other's premises.

Current peers:

- **Neta** — product perception & design sensemaking;
- **R&D Agent** — research & evidence sensemaking.

Future peers should be added only when a recurring class of material questions cannot be handled cleanly by existing peers/authorities and a separate method reduces error or cost.

## Why an orchestrator may exist later

An orchestrator is justified only if peer stability creates a new coordination problem worth solving.

Potential earned functions:

- decompose compound goals;
- route claim dependencies;
- track unresolved handoffs;
- identify authority ceilings;
- preserve conflicts rather than averaging them;
- synthesize a decision state across peer outputs.

The orchestrator is not justified by the mere existence of multiple agents.

## Ecosystem failure to avoid

```text
more agents
→ more outputs
→ more coordination
→ more apparent sophistication
→ unchanged or worse decision quality
```

Coordination itself must buy material uncertainty reduction.

## Success condition

The ecosystem is working when:

- the right question reaches the right peer/authority;
- evidence is proportional to the claim/use;
- duplicate or irrelevant work is avoided;
- disagreements remain legible;
- research/product learning survives the session;
- future work can start from the last valid decision state;
- stopping is treated as success when no admissible work can improve the decision.

## Change rule

A new peer, orchestrator capability or shared-kernel rule must be earned by observed failure in the current architecture, not by architectural elegance.
